Automatic data refresh implementation plan

Approved design: automatic-data-refresh-design.html. Execution: implement in this session, without subagents, as required by the user.

Goal: a weekly GitHub job that updates supported sources automatically and exposes reliable source freshness in the app.

Architecture: a shared TypeScript runner invokes independent source adapters, records each attempt in PostgreSQL, and holds a database advisory lock. Adapters validate complete snapshots and update changed records in transactions. Node 22, pnpm, Prisma and the current PostgreSQL database remain in use.

Global constraints

  • Weekly only: Monday 03:30 UTC / 09:00 IST. Manual dispatch remains available.
  • Use official source dates and links; keep checked/imported dates separate. Preserve newer curated outcomes, transcripts and AI analysis.
  • Never erase records because a source is unavailable. Never log or commit credentials.
  • Historical archives and reviewed governance remain explicitly bounded.

Review focus

  • Source timeout, HTTP 429/5xx and invalid JSON must retry or fail without falsely marking data current.
  • A new session or empty current session must be discovered safely and cannot remove prior data.
  • Stable IDs and equal snapshots must produce no record changes on rerun.
  • Concurrent runs must not compete; a failing source must not prevent other sources from refreshing.
  • Runtime freshness must read the database, rather than a build-time JSON file.
